# 13 — Decision Log

Decisions that are settled. Anything not here is still open in
[09-open-questions.md](09-open-questions.md). Changing a settled decision
requires updating this log with a new dated entry.

| #    | Date       | Decision                                                                                                                                 | Consequence                                                                                                                                                                                                                                                                                         |
| ---- | ---------- | ---------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| D-01 | 2026-08-31 | **v1 targets three personas: lay reader, small-group leader, and pastor/sermon-prep.** Academic/original-language work is explicitly v2. | Commentaries and a capable Resource Reader panel are promoted into v1 scope (FR-LB, M6). Hebrew/Greek, morphology, lexicons and SBL fonts stay out. Sermon-prep workflows (outline notes, export to handout) become first-class. Resolves **A1**, **A4**, **D3**.                                   |
| D-02 | 2026-08-31 | **Open source, free forever.**                                                                                                           | No commercial store, no DRM, no paid tier. Licence must be chosen (see open question G4). No budget for a Windows code-signing certificate unless self-funded — v1 may ship unsigned with documented SmartScreen guidance. Public issue tracker and contributor docs are in scope. Resolves **A2**. |
| D-03 | 2026-08-31 | **Custom workspace layout engine.** No dockview / rc-dock / golden-layout.                                                               | The split-tree model in doc 05 is the source of truth. Layout reducers get exhaustive unit tests and an invariant checker. M2 is the highest-risk milestone; budget accordingly. Resolves **C1**.                                                                                                   |
| D-04 | 2026-08-31 | **Bundle a small public-domain set; download the rest from a signed catalogue.**                                                         | Installer bundles KJV (+ likely WEB). ASV, YLT, Darby and commentaries are catalogue downloads. The catalogue, signing key, and resumable download path are required for v1, not optional. Resolves **E5**.                                                                                         |
| D-05 | 2026-08-31 | **Implementation starts at M0 + M1** — workspace scaffold, hardened Electron shell, frameless chrome, rail, toolbar, theming.            | The panel engine (M2) begins only once the shell is stable. ~~Wayland/Windows-snap spikes happen inside M1~~ — superseded by **D-18**: the Wayland spike is dropped and only the Windows 11 snap-layout question remains in M1.                                                                                                                                                    |
| D-06 | 2026-08-31 | **Offline-first; no telemetry; no account or cloud sync in v1.**                                                                         | Network is used only for the resource catalogue and opt-in updates. Schema is designed to permit sync later. Partly superseded by **D-21**: accounts are now an explicit v2 goal with written requirements, though still absent from v1. The no-telemetry stance is unchanged.                                                                                                                                                        |
| D-07 | 2026-08-31 | **No proprietary resource formats.** Ingestion is USFM/OSIS → our own compiled `.vsres` format.                                          | Rules out Logos/Accordance interop and defers SWORD pending licence review.                                                                                                                                                                                                                         |
| D-08 | 2026-08-31 | **Licence: GPL-3.0-or-later.**                                                                                                           | `LICENSE` at repo root, SPDX headers on source files. Every dependency must be GPL-compatible — **no** SSPL/BSL/CC-BY-NC/proprietary packages or fonts; a CI licence check enforces this. Forks and derivatives must stay open. Resolves **A7**.                                                    |
| D-09 | 2026-08-31 | **Window controls are Windows-style (min, max, close, right-aligned) on both platforms.**                                                | One code path, one visual design, one set of tests. We deliberately ignore the GNOME/KDE `button-layout` setting; note this in the FAQ as an intentional choice. Resolves **B1**.                                                                                                                   |
| D-10 | 2026-08-31 | **Default Bible presentation is one verse per line.**                                                                                    | Study-first default matching Logos and the pastor/leader personas. Paragraph mode remains a per-panel toggle (FR-RD-05) and a global default in Settings. Verse-per-line makes verse anchoring, highlight indicators and margin notes structurally simpler. Resolves **D1**.                        |
| D-11 | 2026-08-31 | **Visual identity: modern dark-first, VS Code / Linear feel.**                                                                           | Dark is the default theme; a light theme is a first-class equal, not an afterthought. Compact, high-contrast, sharp corners (4–6 px radii), dense information display. Reading typography is tuned separately and more generously than UI typography. Resolves **G3**.                              |
| D-12 | 2026-08-31 | **Pursue free OSS Windows signing routes rather than buying a certificate.**                                                             | Investigate SignPath.io's free OSS plan (the main realistic option), plus distribution via `winget` and Chocolatey. If none land, ship unsigned with documented SmartScreen guidance. This is a v1 release blocker to resolve early, not at M8. Resolves **F3**.                                    |
| D-13 | 2026-08-31 | **Secondary contextual sidebar (VS Code style) is in v1 and is a must-have.**                                                            | Rail item → expands a resizable ~280 px panel. Providers for Bible (book/chapter picker), Notes (notebook tree), Library (resource list), Search (query builder + history). Promoted from S to M as FR-SH-12. Resolves **B4**.                                                                      |
| D-14 | 2026-08-31 | **Inactive tabs stay mounted, with an LRU cap of 8 live panels per window.**                                                             | Instant tab switching. Panels beyond the cap unmount but retain serialised state and restore on activation. Every panel must therefore tolerate unmount/remount without data loss — this is a panel contract, tested in M2. Memory budget NFR-03 is measured against the cap. Resolves **C2**.      |
| D-15 | 2026-08-31 | **Single top-level window in v1.**                                                                                                       | FR-SH-08 (multi-window) and FR-WS-10 (floating/detached panels) both move to v2. Simplifies state ownership: one window, one active workspace, one set of link sets. The window manager should still avoid hard-coding a singleton assumption. Resolves **B3** and **C3**.                          |
| D-16 | 2026-08-31 | **v1 commentaries: Matthew Henry and Jamieson-Fausset-Brown (JFB).**                                                                     | Both public domain and widely available in parseable form. The resource compiler needs a commentary path (verse-range-keyed entries) in addition to the Bible path. Other works (Barnes, Gill, TSK) are post-v1 catalogue additions. Resolves **E7**.                                               |
| D-17 | 2026-08-31 | **Placeholder branding for now.**                                                                                                        | A simple SVG wordmark/icon and a generated icon set (ICO, PNG set, Linux hicolor sizes) to unblock packaging. Real artwork can drop in later without code changes. Resolves **G1**.                                                                                                                 |
| D-18 | 2026-08-31 | **Native Wayland support is deferred to v2. v1 ships on X11/XWayland**, which is Electron's default on a Wayland session. | We do not pass `--ozone-platform=wayland` and do not test compositor-native frameless behaviour. Two cheap insurance measures are taken now: (1) window dragging uses `-webkit-app-region` only, never manual `setPosition`, and (2) window-state persistence treats position as best-effort so it degrades cleanly where the platform withholds it. Known accepted cost: fractional-scaling blurriness under XWayland on HiDPI. Removes the M1 spike. Resolves **B2**; amends **D-05**, **FR-SH-04**, **NFR-11**. |
| D-19 | 2026-08-31 | **Scroll sync across linked panels is a v1 must-have**, covering Bibles, commentaries and notes panels alike. | FR-WS-08 promoted S→M; new FR-WS-13/14/15. Sync anchors on **verse keys, not pixel proportions** — heterogeneous content lengths make proportional sync useless. Every linkable panel must implement `getAnchorAtViewportTop` and `scrollToVerse`, which becomes part of the panel contract in M2 and constrains how Bible rendering virtualises in M3. Notes panels become linkable, which they were not before. |
| D-20 | 2026-08-31 | **Personal commentary is a v1 feature**: a notebook can be designated a commentary and behaves as a first-class resource. | New FR-NT-09..13. Implemented as a **view over existing notes**, not a second store: `notebook.kind = 'commentary'` plus verse-range anchors that already exist. Personal commentaries appear in the Library, open in a commentary panel, join link sets, and can be exported as `.vsres` for others to import. Adds a user-authored path into the resource system that M6 must accommodate. |
| D-21 | 2026-08-31 | **Accounts and sign-in are a planned v2 capability**, specified now but not built in v1. Supersedes part of **D-06**. | New FR-AC-01..09. Hard constraints carried forward: sign-in is always optional, the app stays fully functional offline forever, and there is no first-run prompt. v1 pays only for schema readiness — UUID primary keys, UTC timestamps, and a migration path for deletion tombstones. Resources are never synced, only user data. Open questions **H1–H5** must be answered before any implementation. |
