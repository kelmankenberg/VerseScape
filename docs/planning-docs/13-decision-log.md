| D-24 | 2026-08-31 | **Library and backup locations are user-configurable; the live database's is not.** | New FR-LB-08/09 and FR-ST-06/07/08. | D-25 | 2026-08-31 | **Every syncable panel owns a slim header carrying a reference input and its sync-set badge.** Any panel can drive its set; none is privileged. | New FR-WS-17/18/19; FR-RD-02 generalised from "the Bible panel's nav bar" to a shared parser used by every panel header. | D-28 | 2026-09-01 | **One SQLite engine. `better-sqlite3` is built for Electron's ABI, and the resource compiler runs under `ELECTRON_RUN_AS_NODE=1 electron`.** | The compiler writes resource databases and the app reads them, so both must agree on the file format — above all on **FTS5**, since the compiler pre-builds the search index (doc 07). Two engines (`node:sqlite` for tooling, `better-sqlite3` for the app) would have meant two SQLite builds that must agree on FTS5 availability, tokenizer configuration and page-size defaults, plus two determinism profiles for the byte-identical build guarantee. One engine removes that class of problem entirely. **Cost:** the emitter cannot be unit-tested by Vitest, which runs on Node's ABI. It is covered instead by `pnpm compiler:check`, an integration self-test that compiles a fixture, reads it back and verifies determinism. Verified on this machine: FTS5 with `unicode61 remove_diacritics 2` works under Electron, SQLite 3.53.4. |
| D-29 | 2026-09-01 | **CCEL stays as the commentary source, with permission to be procured.** Resources now declare `redistributable` and any `restrictions`. | CCEL's published terms ("personal, educational, or non-profit purposes"; "contact us for permission to republish") do not by themselves permit redistribution by the app's recipients, which GPL-3.0 grants them. Rather than switch sources, we seek written permission. What the grant must cover is recorded in `LICENSES.md`: **preferred** is CC BY 4.0 or public domain on CCEL's transcriptions of these two works, since the underlying works are already public domain; **acceptable** is permission that extends to recipients redistributing unmodified; **insufficient** is permission for this project alone. A resource is legal to ship either way because resource databases are mere aggregation, delivered as separate catalogue downloads (D-04) rather than linked into the program — but a resource marked `redistributable: false` cannot be bundled in an installer and packagers must be able to exclude it. Compilation is blocked until the grant is recorded. Supersedes the earlier exclusion; **E11** now tracks the permission rather than a replacement source. |

| D-27 | 2026-08-31 | **Online API-delivered translations (ESV, LSB, NIV, …) are deferred. The resource model keeps the door open via `deliveryMode: 'local' \| 'online'`.** | The decisive argument is **search**, not reading: a reference API cannot serve ranked full-text results, so an online translation would be *silently absent* from cross-resource search. In a study tool that is a wrong answer, not a degraded feature. Secondary blockers: an open-source binary cannot ship an API key, so every user would need their own; "free for non-commercial use" sits badly with GPL-3.0; sync sets (D-23) would break mid-set when the network drops; and LSB appears to have no public API at all. New FR-LB-10/11 encode the rules that would apply if this is ever revisited. Cost of keeping the option open: one manifest field. |
